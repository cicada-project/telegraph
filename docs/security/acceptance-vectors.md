# Telegraph R4 acceptance vectors

These are executable test contracts for ADR 0002. They do not prove that Telegraph has encryption. The harness must run each vector against the pinned `vodozemac 0.10.0` adapter and a fake relay/mailbox. The relay fixture is allowed to inspect only the outer envelope and its database; the endpoint fixture is the only plaintext consumer.

## Fixture generation rule

The YAML below is the normative test data. Hashes and canonical CBOR are generated from the stated bytes and tables; no hand-written ciphertext is valid test data.

* Non-cryptographic fixtures use the explicit byte values and `clock_start`/`clock_delta` values below. The user-code fixture uses the 50-bit integer `0x0123456789AB` and must encode to `014D2PF2DB` (UI grouping `014D2-PF2DB`).
* A crypto fixture is generated by a Rust helper compiled against the exact full vodozemac commit. It creates accounts, one-time keys, sessions, pickles, and Olm messages through the public `Account`/`Session` APIs. If the adapter cannot inject deterministic randomness, it records generated outputs in a fixture artifact and tests only the stated invariants; it must never paste or synthesize a ciphertext.
* Generated ciphertext is identified by `{fixture_id, implementation_commit, plaintext_sha256, ciphertext_sha256}` and is discarded from the relay-database assertion after use. A vector may assert decryptability, equality under retry, and failure under mutation, but must not contain a fabricated base64/hex ciphertext.
* Every generated fixture must assert the library version/commit, canonical plaintext bytes, session ID equality at both ends, OTK ID equality, and successful `pickle -> restore` before testing the vector.
* A storage fixture serializes the raw `AccountPickle`/`SessionPickle` first, then applies independent XChaCha20-Poly1305 with a fresh random 24-byte nonce, 16-byte tag, per-record HKDF key, and exact AAD `{record_type, record_id, record_schema, record_version}`. It must never call vodozemac/library pickle encryption, reuse a nonce, or put `K_storage_master` in SQLite. The master key fixture comes from a fake OS credential-store backend; unavailable/restore/rotation/erase failures are expected fail-closed outcomes.
* The relay fixture parses the public vodozemac Olm header and records sender/base/OTK/ratchet public keys and chain/message index as metadata. This is intentionally visible and correlatable; only inner plaintext and private keys are forbidden to the relay.
